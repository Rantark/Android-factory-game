# Factory Flow

A relaxing, Factorio-inspired factory-automation game for Android. You get a top-down
view of a procedurally generated world, and you build mines, belts, smelters,
assemblers, refineries and labs until the factory runs itself. There are no enemies
and no combat. It's about efficiency, expansion and watching things flow.

Every visual and every sound is generated by code at runtime. The project contains **no
image, sprite, font or audio files**.

---

## Get the game on your phone

1. On your Android phone, open the repository's **Releases** page:
   `https://github.com/Rantark/Android-factory-game/releases`
2. Tap **`FactoryFlow.apk`** under the newest release. The direct link, which always
   points at the newest build, is:

   ```
   https://github.com/Rantark/Android-factory-game/releases/latest/download/FactoryFlow.apk
   ```
3. When the download finishes, tap it. Android will ask you to allow **Install unknown apps** for
   your browser (Settings → Apps → *your browser* → Install unknown apps → Allow).
4. Tap **Install**, then **Open**.

Requires Android 8.0 (API 26) or newer. The game plays in landscape.

> **Updating:** if the APK was built *without* your own signing key (see below), every CI
> run signs it with a fresh debug key. Android then refuses to install it over the
> previous version ("App not installed"). Uninstall the old version first (this deletes
> saves), or set up release signing once so updates install in place and keep your saves.

## Build & publish (one tap, no local tools)

**▶ Build button:** https://github.com/Rantark/Android-factory-game/actions/workflows/build.yml
→ **Run workflow** → **Run workflow**. (Forked it? Use `https://github.com/<you>/<repo>/actions/workflows/build.yml`.)

A build is started by:

- **any push to any branch**, or
- the **Run workflow** button above.

Each build runs the tests, builds the APK and **publishes a GitHub Release**. The newest
APK is always at:

```
https://github.com/Rantark/Android-factory-game/releases/latest/download/FactoryFlow.apk
```

Pull requests build and test but don't publish.

### Versioning

The version lives in code, in [`version.properties`](version.properties):

```properties
version=1.0.0
```

- The release **tag is `v<version>`**, e.g. `v1.0.0`. The app shows the same version in its
  Menu (for example "1.0.0 (build 7)").
- To release a new version, change the number (e.g. to `1.1.0`) and push. That publishes `v1.1.0`.
- If you build again without changing the number, the build is **still published**, as
  `v1.0.0-build.<run number>`, so a run never fails because a tag already exists.
- The Android `versionCode` is the workflow run number, so every build installs as an
  upgrade of the previous one.

### What the pipeline does (`.github/workflows/build.yml`)

| Step | Details |
| --- | --- |
| Set up JDK 17 + Android SDK 36 | Uses the SDK preinstalled on `ubuntu-latest` |
| Gradle with caching | `gradle/actions/setup-gradle` |
| Unit tests | `./gradlew :core:test`: simulation, placement, save/load, audio levels, render cost |
| Version | Reads `version.properties` → tag `v<version>` (or `v<version>-build.<run>` if taken) |
| Build | `./gradlew :android:assembleRelease`; `versionName` = version, `versionCode` = run number |
| Publish | `gh release create` (GitHub CLI, preinstalled) uploads `FactoryFlow.apk`; the run summary shows the links |

### Release signing (optional, recommended)

Without these secrets the APK is signed with a throw-away debug key, which is fine for a
first install. To get stable signatures so updates install over the old version, add
these **repository secrets** (Settings → Secrets and variables → Actions → New
repository secret):

| Secret | Value |
| --- | --- |
| `KEYSTORE_BASE64` | Your keystore file, base64-encoded |
| `KEYSTORE_PASSWORD` | The keystore password |
| `KEY_ALIAS` | The key alias inside the keystore |
| `KEY_PASSWORD` | The key's password |

To create a keystore once on any machine with a JDK:

```bash
keytool -genkeypair -v -keystore factoryflow.jks -alias factoryflow \
        -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 factoryflow.jks > factoryflow.jks.b64   # macOS: base64 -i factoryflow.jks
```

Paste the contents of `factoryflow.jks.b64` into `KEYSTORE_BASE64`. Keep the `.jks` file
somewhere safe: if you lose it, future builds can no longer update existing installs.

## How to play

**Goal:** deliver items to the golden **Factory Core**. Everything that reaches the Core
becomes building stock, which you spend on more buildings. Research technologies to unlock
new machines and aim for the final research, *Factory Ascension*.

**A first factory**

1. **Extract → Mining Drill:** tap a spot on an ore patch to move the ghost, then tap
   the ghost again to build. The arrow shows where the ore comes out.
2. **Power → Power Pole:** drills need electricity. The Core supplies 400 kW to its
   surroundings; chain poles (8-tile reach) out to your drills.
3. **Belts → Conveyor Belt:** drag from the ghost to paint a belt line from the drill
   into the Core. The line turns an L-shaped corner automatically.
4. **Process → Stone Furnace:** put it in front of a drill, or feed it by belt. It picks its
   recipe from the ore it receives and burns coal, so bring it a coal belt too.
5. **Process → Assembler:** tap it and choose a recipe (gears, wire, circuits, science…).
   Belts pointing into a machine feed it; products leave through its arrow side.
6. **Research → Lab:** feed it science packs and pick a technology in **Tech**.

**Controls**

| Action | Gesture |
| --- | --- |
| Pan | Drag with one finger (flings glide) |
| Zoom (0.3×–3×) | Pinch |
| Inspect a building | Tap it: shows rates, power, contents, recipe picker, rotate and remove |
| Build | Pick a category → pick a building → tap to place the ghost → tap the ghost again (or **Build**) |
| Paint belts/pipes/poles | In build mode, drag starting on the ghost |
| Rotate | **Rotate** button while placing, or in a building's info panel |
| Remove | **Remove** toggles bulldozer mode; materials are fully refunded |
| Undo | **Undo** reverts your last 10 actions (a painted line counts as one) |
| Close a panel | Swipe it down, tap ✕, or press Android Back |
| Game speed | **1x / 2x / 4x** button |
| Save / load | **Menu**: 3 slots, plus auto-save every 5 minutes and on leaving the app |

**Tips**

- Inserters only grab items their destination actually needs, so they never clog a machine.
- The fluids you get from a refinery each need their own pipe. A pipe network remembers
  its fluid, so byproducts can't contaminate a line. A refinery vents byproducts it has
  nowhere to send, so it never jams.
- Solar panels produce nothing at night. Accumulators store daytime surplus.
- **Stats** shows production and consumption per minute, a power graph, and how long each
  deposit will last at the current mining rate.

## Content overview

- **World:** 512×512 tiles, seeded noise with five blended biomes (Grassland, Rocky
  Highlands, Sandy Flats, Dense Forest, Wetlands), lakes, and clustered deposits of
  iron, copper, coal, stone, rare crystal and oil. The start is always a flat clearing
  with mixed deposits nearby. A minimap shows explored terrain.
- **31 building types:** mining drill, pump jack, water pump; belts, underground belts,
  splitters, mergers, pipes, four inserter types; power poles and towers, coal
  generators, solar panels, accumulators; stone and electric furnaces, three assembler
  tiers, chemical plant, oil refinery, electronics factory; three chest tiers and
  storage tanks; research lab; the Core.
- **Production chain:** 26 items and 6 fluids across 5 tiers, from ore → plates → steel,
  gears, wire → circuits, engines, pipes → advanced circuits, machine frames, plastic,
  sulfur, batteries → crystal shards and quantum chips. Oil processing and cracking
  are included.
- **Research:** 5 science packs and 36 technologies that unlock buildings, recipes, and
  belt, mining, lab, inserter, crafting and solar bonuses.
- **Day/night:** a 20-minute cycle. The world darkens, working machines glow, solar
  stops, and accumulators drain.
- **Audio:** a real-time software synthesizer produces all of it. Wind shaped per biome
  (a highland whistle, the hiss of sand), birdsong by day and crickets at night, frogs
  in the wetlands, per-category machine hums (drill pulse, furnace crackle, belt whir,
  assembler rhythms, generator hum), and soft UI clicks, chimes and warnings. A gentle
  limiter keeps it from ever sounding harsh.

## Why Kotlin + libGDX

I evaluated four stacks against the requirements: CI-only builds, procedural vector
graphics, procedural audio, 200+ simulated machines at 60 fps, and stable GitHub
Actions tooling.

| | Flutter + Flame | Kotlin + Android Canvas | Java + libGDX | **Kotlin + libGDX** |
| --- | --- | --- | --- | --- |
| CI build | Good (Flutter action) | Excellent (plain Gradle) | Excellent | **Excellent (plain Gradle/AGP)** |
| Procedural vector 2D | Good (Canvas/Skia) | Good, but one draw call per shape | Excellent: custom meshes and shaders | **Excellent** |
| Raw PCM synthesis | Weak: needs third-party plugins | Good (`AudioTrack`) | Excellent (`AudioDevice`) | **Excellent** |
| 200+ machines, thousands of belt items | Risky: Dart→Skia per-shape overhead | Risky: thousands of Canvas calls per frame | Excellent: batched geometry | **Excellent** |
| Desktop build for testing | Yes | No | Yes | **Yes** |
| Code ergonomics | Good | Good | Verbose | **Concise, null-safe** |

**Kotlin + libGDX** won:

- **Rendering:** a custom `VectorBatch` streams every shape as coloured triangles, and
  text as glyph quads, through one shader and one texture. A typical frame is about
  10 draw calls regardless of factory size, and terrain is baked into one static mesh
  per 32×32 chunk.
- **Audio:** `AudioDevice` accepts raw 16-bit PCM, so the synthesizer is just a loop
  that writes samples.
- **Pipeline:** the build is plain Gradle + Android Gradle Plugin, which runs on stock
  `ubuntu-latest` runners.
- **Testing:** the same core runs on the desktop (LWJGL3), which allowed automated
  screenshots and headless tests during development.

### Zero assets

- **Graphics:** all graphics are code-generated. See `render/Painter.kt` (buildings,
  items, icons) and `render/TerrainRenderer.kt` (terrain and decorations).
- **Text:** at startup each glyph is rasterized from the device's built-in system font
  (Android `Canvas`) into an in-memory atlas. No font files ship with the game.
- **Audio:** everything is synthesized per sample (`audio/AudioEngine.kt`).
- **Launcher icon:** a vector drawable written as path data.

## Performance design

- **Fixed-step simulation (60 Hz):** 1×/2×/4× speed runs extra steps. Chunks far from
  the viewport are simulated every 4th step with a 4× time step, so the whole
  factory keeps producing at a fraction of the CPU cost.
- **Zero-garbage belts:** belt items live in preallocated primitive arrays per belt tile.
  This is object pooling taken to its limit: no per-item objects and no GC churn.
- **Culling:** only chunks and buildings in view are drawn, and far-zoom rendering drops
  small details.
- **Caching:** power and fluid networks are rebuilt only when the layout changes, and
  neighbour lookups are cached against a layout version number.
- **Measured (JVM, CI test):** 220 assemblers plus belts tick in well under 2 ms, and
  full-detail geometry for 1,500 buildings is generated in about 1.5 ms.

## Project layout

```
core/        game code (platform independent)
  data/      items, fluids, recipes, buildings, tech tree
  world/     noise, biomes, deposits
  sim/       factory simulation, power, fluids, research, stats, undo, save format
  gfx/       vector batch, shapes, runtime font atlas
  render/    procedural painter, terrain chunks, world renderer, minimap
  ui/        immediate-mode UI toolkit and the HUD
  audio/     software synthesizer
  game/      app entry point, camera, controls, session, save slots
android/     Android launcher (glyph rasterizer, manifest, vector icon)
desktop/     desktop launcher for development and screenshots (not shipped)
```

With JDK 17+ and the Android SDK installed:

```bash
./gradlew :core:test                    # headless tests
./gradlew :android:assembleRelease      # APK → android/build/outputs/apk/release/
./gradlew :desktop:run --args="--demo"  # play on the desktop (mouse = touch, wheel = zoom)
```
